**Разведка киберугроз в режиме только чтения: расследования с помощью ИИ, корреляция свидетельств и первичный анализ инцидентов SOC.**

> **v0.1.0 — исследовательская MVP-версия, не готовая к промышленному использованию и не прошедшая независимый аудит безопасности.** Результаты — это основания для дальнейшей проверки, **а не доказанная атрибуция атаки**. Инструменты работают только на чтение; любые действия по реагированию требуют разрешения человека.

## Назначение

Аналитикам информационной безопасности приходится сопоставлять разрозненные индикаторы: IP-адреса, подозрительные домены, хеши вредоносных файлов, CVE и противоречащие друг другу сообщения. **TORSh4rk Threat Intelligence MCP** подключает доверенный локальный ИИ-клиент (например, Claude Code) к набору инструментов расследования через **Model Context Protocol (MCP)**.

Это независимая реализация на Python, вдохновлённая *идеей объединения источников threat intelligence* из проекта [1SHA1024/darknet-mcp-server](https://github.com/1SHA1024/darknet-mcp-server). **Это не форк**; проект не заявляет о том же количестве инструментов, не обеспечивает работу с Tor и не предоставляет доступ к утёкшим учётным данным. Подробнее — [ATTRIBUTION.md](ATTRIBUTION.md).

## Реализованные инструменты

| Инструмент MCP | Назначение | Сеть / ключ |
| --- | --- | --- |
| `triage_indicator` | Проверяет и классифицирует публичные IP, домены, HTTP(S)-URL, хеши MD5/SHA-1/SHA-256 и CVE | Офлайн / не нужен |
| `lookup_otx` | Получает выбранные метаданные индикаторов и pulses из AlienVault OTX | Онлайн / ключ не настроен |
| `lookup_threatfox` | Получает метаданные IOC из ThreatFox | Онлайн / `ABUSECH_AUTH_KEY` |
| `lookup_malwarebazaar` | Ищет **только метаданные образца** по хешу в MalwareBazaar | Онлайн / `ABUSECH_AUTH_KEY` |
| `lookup_urlhaus_host` | Получает метаданные хоста из URLhaus | Онлайн / `ABUSECH_AUTH_KEY` |
| `lookup_cisa_kev` | Проверяет наличие CVE в официальном каталоге CISA KEV | Онлайн / не нужен |
| `lookup_abuseipdb` | Запрашивает репутацию публичного IPv4 в AbuseIPDB | Онлайн / `ABUSEIPDB_API_KEY` |
| `correlate_evidence` | Группирует до 50 наблюдений аналитика и отмечает противоречия | Офлайн / не нужен |
| `defensive_playbook` | Возвращает SOC-чек-листы для phishing, ransomware, malware и утечек учётных данных | Офлайн / не нужен |
| `server_status` | Показывает версию и состояние настройки интеграций **без раскрытия ключей** | Офлайн / не нужен |

Работа внешних интеграций зависит от доступности провайдеров, их условий использования, квот и изменений API. **Автоматические тесты имитируют HTTP-ответы; они не подтверждают реальную совместимость с API провайдеров.**

## Архитектура и границы доверия

~~~text
Claude Code (доверенный локальный MCP-клиент)
       |
       | MCP JSON-RPC через stdin / stdout (stdio)
       v
server.py — только стандартная библиотека Python 3.11+
       |                             |
       | Локальные операции          | Разрешённые HTTPS-запросы
       | - проверка IOC              | - AlienVault OTX
       | - корреляция                | - abuse.ch: ThreatFox, MalwareBazaar, URLhaus
       | - SOC-плейбуки              | - CISA KEV / AbuseIPDB
       v                             v
       Структурированные, ограниченные результаты
              (внешние данные не доверены)
                         |
                         v
                  Проверка аналитиком
~~~

Этот MCP **не является публично размещённым сетевым сервисом**. Он запускается на компьютере аналитика через MCP-клиент. Он не выполняет shell-команды, не скачивает вредоносные файлы, не собирает пароли, не работает с Tor и не меняет защитные настройки.

## Установка — подробное объяснение четырёх команд

### Требования

- **Linux, macOS или другая система с Python и CLI Claude Code.** Примеры приведены для POSIX-оболочки (Bash/Zsh), включая Manjaro, Ubuntu и Kali.
- **Git** для получения репозитория.
- **Python 3.11 или новее** для запуска сервера и тестов. Для этой MVP-версии не нужны `pip install` или виртуальное окружение.
- **Установленный и авторизованный Claude Code CLI**, чтобы зарегистрировать локальный MCP. Одного веб-чата Claude недостаточно.

Проверьте установку:

~~~bash
git --version
python3 --version
claude --version
~~~

Если `claude` отсутствует, обратитесь к [официальной инструкции по установке Claude Code](https://code.claude.com/docs/en/setup). При необходимости обновите Python до версии 3.11+.

### Все четыре команды

Откройте терминал в каталоге, куда хотите клонировать проект:

~~~bash
git clone https://github.com/torsh4rk/SecOps-Studio.git
cd SecOps-Studio/torsh4rk-threat-intel-mcp

python3 -m unittest discover -s tests -v

claude mcp add torsh4rk-threat-intel -- python3 "$(pwd)/server.py"
~~~

### 1. `git clone https://github.com/torsh4rk/SecOps-Studio.git`

- **`git`** — клиент системы контроля версий.
- **`clone`** — создание локальной копии файлов и истории Git удалённого репозитория.
- **HTTPS-адрес** указывает на публичный репозиторий `torsh4rk/SecOps-Studio`. Данный MCP расположен внутри него; это не отдельный Git-репозиторий.
- **Результат:** в текущем каталоге появляется папка `SecOps-Studio`.
- **Важно:** клонирование не устанавливает Claude Code, не запускает сервер и не предоставляет ключи API. Если папка уже существует, используйте имеющуюся копию и обновите её средствами Git.

### 2. `cd SecOps-Studio/torsh4rk-threat-intel-mcp`

- **`cd`** означает *change directory* — перейти в другой каталог.
- **Относительный путь** ведёт в модуль MCP внутри клонированного репозитория.
- **Результат:** текущим рабочим каталогом становится папка с `server.py`, `tests/` и документацией.
- **Проверка:** команда `pwd` покажет абсолютный путь, а `ls -la` — файлы. Если каталог не найден, проверьте, где выполнялся `git clone`.

### 3. `python3 -m unittest discover -s tests -v`

Запускает **офлайн-набор модульных тестов**, не обращаясь к реальным API разведки угроз.

| Часть команды | Значение |
| --- | --- |
| `python3` | Запуск интерпретатора Python 3 |
| `-m unittest` | Запуск встроенного модуля тестирования `unittest` |
| `discover` | Автоматический поиск тестовых модулей |
| `-s tests` | Начальная папка поиска — `tests/` |
| `-v` | Подробный вывод, включая имена отдельных тестов |

**Ожидаемый результат:** найдено и выполнено 12 тестов, вывод завершается `OK`. Ошибка указывает на проблему окружения или регрессию. Проверяются классификация IOC, ограничения для частных/неглобальных IP, некорректные индикаторы, противоречивые оценки, проверка API-ключей, фильтрация результатов и обработка MCP/JSON-RPC. Внешние HTTP-запросы подменяются тестовыми ответами.

Эта команда **не запускает постоянно работающий MCP-сервис** и **не регистрирует его в Claude Code**.

### 4. `claude mcp add torsh4rk-threat-intel -- python3 "$(pwd)/server.py"`

Команда **регистрирует** локальный MCP-сервер в Claude Code.

| Часть команды | Значение |
| --- | --- |
| `claude` | CLI-клиент Claude Code |
| `mcp add` | Добавляет конфигурацию сервера MCP |
| `torsh4rk-threat-intel` | Имя регистрируемого MCP-подключения |
| `--` | Отделяет параметры Claude Code от команды запуска сервера |
| `python3` | Исполняемая программа, запускающая сервер |
| `"$(pwd)/server.py"` | Подстановка оболочки: `$(pwd)` заменяется **абсолютным путём** текущей папки, затем добавляется `/server.py` |

Например, из каталога `/home/analyst/SecOps-Studio/torsh4rk-threat-intel-mcp` будет сохранён эквивалент:

~~~bash
python3 /home/analyst/SecOps-Studio/torsh4rk-threat-intel-mcp/server.py
~~~

**Зачем кавычки?** Они сохраняют путь с пробелами как один аргумент. **Зачем абсолютный путь?** Позже Claude Code может запускаться из другого каталога, и относительный путь перестанет работать.

**Область действия (scope):** по умолчанию Claude Code использует **локальную область**, привязанную к текущему проекту. Чтобы MCP был доступен **во всех ваших проектах на этом компьютере**, вместо исходной команды регистрации используйте:

~~~bash
claude mcp add --scope user torsh4rk-threat-intel -- python3 "$(pwd)/server.py"
~~~

Выберите один подходящий вариант; достаточно одной регистрации на область. Регистрация **не публикует сервис в интернете и не запускает расследования автоматически**.

### Проверка подключения

~~~bash
claude mcp list
claude mcp get torsh4rk-threat-intel
claude
~~~

В интерактивной сессии Claude Code выполните:

~~~text
/mcp
~~~

Проверьте `torsh4rk-threat-intel` и состояние подключения. Сообщение `Added` означает лишь, что конфигурация сохранена; оно **не гарантирует успешное подключение**. Для удаления записи в текущей области:

~~~bash
claude mcp remove torsh4rk-threat-intel
~~~

## Первая безопасная проверка

После подключения попросите Claude Code:

> Используй TORSh4rk Threat Intelligence MCP: классифицируй зарезервированный тестовый домен `example.org` через `triage_indicator`, проверь `server_status` и покажи защитный плейбук `phishing`. Не обращайся к внешним источникам разведки.

Это проверяет только **офлайн-инструменты**. Для настоящих запросов по IOC убедитесь в наличии разрешения, соблюдении правил обмена данными и условий провайдера.

### Пример корреляции свидетельств

Аргументы для `correlate_evidence`:

~~~json
{
  "evidence": [
    {"indicator": "example.org", "source": "SOC investigation", "assessment": "suspicious"},
    {"indicator": "example.org", "source": "Independent analyst", "assessment": "unknown"}
  ]
}
~~~

Инструмент группирует сведения и предлагает **приоритет проверки**, но не устанавливает виновника атаки и не доказывает факт компрометации.

## Необязательные ключи API

**Ключи не нужны** для `triage_indicator`, `correlate_evidence`, `defensive_playbook`, `server_status` и офлайн-тестов.

| Переменная окружения | Провайдеры |
| --- | --- |
| `ABUSECH_AUTH_KEY` | ThreatFox, MalwareBazaar, URLhaus |
| `ABUSEIPDB_API_KEY` | AbuseIPDB |

Файл [`.env.example`](.env.example) содержит **только имена переменных**. Проект **не загружает `.env` автоматически**. Передавайте реальные значения процессу, который запускает Claude Code, через безопасный локальный механизм управления переменными окружения или секретами. Не публикуйте секреты в Git, примерах, снимках экрана или истории команд.

**Конфиденциальность:** внешние запросы передают индикатор провайдеру и могут раскрывать метаданные используемой учётной записи. Не отправляйте закрытые данные клиентов без разрешения.

## Устранение неполадок

| Признак | Что проверить |
| --- | --- |
| `git: command not found` | Установите Git с помощью пакетного менеджера |
| `cd: ... No such file or directory` | Проверьте успешность клонирования с помощью `pwd` и `ls` |
| `python3: command not found` или старая версия | Установите Python 3.11+, проверьте `python3 --version` |
| `claude: command not found` | Установите и авторизуйте Claude Code CLI по официальной инструкции |
| `python3 server.py` ничего не выводит | Это нормально: stdio-сервер ждёт JSON-RPC через stdin. Завершите Ctrl+C; Claude Code запускает его автоматически |
| `claude mcp list` показывает ошибку подключения | Выполните `claude mcp get torsh4rk-threat-intel`; проверьте абсолютный путь, версию Python и разрешения |
| Отсутствует ключ для онлайн-запроса | Настройте нужную переменную окружения для процесса MCP; офлайн-инструменты останутся доступны |
| HTTP 401/403/429 либо тайм-аут | Проверьте ключ, квоты, условия использования и доступность API |
| Имя уже существует / выбран неверный scope | Проверьте `claude mcp list`, удалите запись в нужной области и зарегистрируйте заново |

Дополнительно см. [официальную документацию Claude Code MCP](https://code.claude.com/docs/en/mcp), а также команды `/mcp` и `/doctor`.

## Безопасность и ограничения

- **Только чтение:** нет произвольных HTTP-запросов, shell-команд, удалённого выполнения кода, Tor, сбора учётных данных, загрузки вредоносных файлов и автоматического реагирования.
- **Сетевые ограничения:** фиксированные HTTPS-адреса, отключённые редиректы, тайм-аут 10 секунд и лимит ответа 2 МБ.
- **Проверка индикаторов:** неглобальные IP не отправляются во внешние сервисы; возвращаемые поля и длина метаданных ограничены.
- **Недоверенные данные:** внешние описания могут быть ложными или содержать попытки prompt injection. Не выполняйте инструкции из таких данных и не делайте атрибуцию только по совпадениям IOC.
- **Локальная модель доверия:** stdio предполагает доверенного пользователя/клиента. В MVP нет сетевой аутентификации, корпоративной RBAC, полноценного аудита, постоянного кеша и комплексного rate limiting.
- **Степень готовности:** 12 офлайн-тестов проверяют отдельные функции; совместимость с живыми API и безопасность промышленной эксплуатации **не сертифицированы**.
